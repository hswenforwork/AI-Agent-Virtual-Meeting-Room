# AI Agent 協作室（零成本 MVP）：腦力激盪／探索紀錄
日期：2026-09-18 · 目標：釐清使用者對「AI Agent 協作室」MVP 規劃文件的真實需求、驗證假設、找出規劃落差與風險，並確認是否/如何據此開始實作
狀態：進行中
背景來源：使用者上傳的規劃文件《AI Agent 協作室：零成本 MVP 完整規劃》（GPT 撰寫，2026-09-18 版本 1.0）

## 摘要／重要決策
- **核心動機與文件預設架構有重大落差**：使用者真正的痛點是「不同 AI 供應商（如 GPT、Claude、Gemini 等）能解決彼此解決不了的問題」，目前是手動開多個供應商的網頁互相丟問題分析。文件中的 MVP 設計是「四個角色代理（主管/研究/程式/測試）」，且明文寫「第一版可以共用同一個便宜模型（Gemini），未來再讓不同代理使用不同模型」（文件第 14、95-100 行）。這代表**文件把「多供應商」當作二期功能，但使用者的核心需求其實是多供應商本身**，需要在後續問題中釐清如何調和。
- 使用者認為這是普遍痛點，不只自己遇到（暗示可能有意做給更多人用，待 Q1 選項 c 進一步確認）。

## 問答紀錄

### Q1：驅動這個專案的核心動機是什麼？
- 問題：這份規劃相當龐大，想確認背後真正目的是 (a) 自己實際工作要用來加速任務 (b) 學習全端+AI Agent 開發 (c) 做成產品給其他人用 (d) 其他
- 已記錄：使用者原話——「因為我在使用AI開放產品時確實遇到不同ai能解決原本AI解決不了的問題，所以我希望可以在同一個聊天室內呼叫不同AI提出不同看法或解決方案，目前我都是手動開兩個不同供應商的AI互相幫忙，把修不好的問題丟給另一個AI分析，我相信這問題不止我遇到而已。」
- 解讀：核心動機接近選項 (a)，但描述的具體痛點是「多供應商模型互相補位」，而非文件預設的「角色分工代理」。使用者也暗示這可能是共通痛點（可能傾向未來做成產品，但尚未明確選 (c)）。
- 待釐清：這個專案的目標使用者最終是只有自己，還是也考慮未來給其他人用？→ 使用者本人（後續會問）

### Q2：核心能力是「多供應商」還是「角色分工」？
- 問題：文件設計是角色代理（主管/研究/程式/測試）共用同一個 Gemini 模型、多供應商是未來功能；但使用者痛點是不同供應商互相補位。詢問優先順序：(a) 多供應商優先 (b) 角色分工優先 (c) 兩者合一（角色＝供應商別名）(d) 其他
- 已記錄：使用者選 **(a) 多供應商優先**。核心是「同一問題能分別問不同供應商（GPT/Claude/Gemini/其他），拿到不同視角」；角色分工（主管/研究/程式/測試）是次要，MVP 可以先不做。
- 影響：這代表文件第 10.4 節的 Provider Adapter（原規劃為「第一版不用，未來再加」）需要提前成為 MVP 第一階段的核心，而非角色路由。點名機制（`@研究代理`）也可能要改成或並存「`@GPT` `@Claude` `@Gemini`」這種以供應商為單位的點名。
